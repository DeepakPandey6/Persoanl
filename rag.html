02 — User Query

This is what the user asks the RAG system.

03 — Chunking

The document is split into smaller pieces. In a real RAG system, chunking strategies can be much more sophisticated.

Waiting

04 — Embeddings

Each chunk is converted into a vector representing its semantic meaning. These numbers are simplified for learning.

05 — Vector Database

The chunk embeddings are stored so they can later be searched using a user's query embedding.

Indexed
Think of this as:

Chunk text + its embedding → stored together in a vector database.

When the user asks something later, the system searches this database for vectors that are mathematically close to the query vector.

06 — Query Embedding

The user's question is converted into an embedding too.

Important: the query is embedded. It is not normally "chunked" first.

07 — Similarity Search

Compare the query embedding with the stored chunk embeddings.

08 — Retrieved Context

The most relevant chunks are passed to the LLM as context.

Run the RAG simulator to retrieve context.

09 — LLM Generation

The LLM receives the user question plus retrieved context, then generates an answer.

The RAG Mental Model

The simplest way to remember the entire architecture.

1. STORE

Documents are split into chunks and converted into embeddings. Those embeddings are stored in a vector database.

2. RETRIEVE

The user's query is converted into an embedding. Similarity search finds the most relevant chunks.

3. GENERATE

The retrieved chunks are provided to the LLM as context. The LLM uses that context to generate the answer.
